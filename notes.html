4. Top Interview Questions & Model Answers

Q1: Why did you use Vanilla JavaScript instead of React, Angular, or Vue?
Answer: "For a localized bespoke tailoring website, loading a 150KB+ React bundle causes unnecessary overhead and slower initial load times on mobile 4G/3G networks. Vanilla ES6+ provides zero-dependency lightweight code, sub-400ms First Contentful Paint (FCP), and direct DOM control. For reactive features like our live price calculator and modal lightbox, modern ES6+ handles state cleanly without framework bloat."
Q2: How does the live order calculator work technically?
Answer: "Each garment card stores its unit rate in a HTML5 data-price attribute. When a user clicks the plus/minus stepper or inputs a number, an event listener calls calculateTotal(). The function iterates over all garment cards using querySelectorAll(), reads the quantity, computes the item total, updates the DOM subtotal, formats the grand total using toLocaleString('en-IN'), and toggles an active .has-qty CSS class for visual feedback."
Q3: Why use WhatsApp for ordering instead of a standard e-commerce payment gateway?
Answer: "Bespoke tailoring is fundamentally personalized: master tailors need to confirm physical measurements, discuss fabric drape, and schedule fitting trials before cutting expensive fabrics. A rigid payment gateway introduces checkout friction and transaction fees. By bridging the order to WhatsApp, the master tailor receives a structured digital invoice while immediately establishing a 1-on-1 direct customer relationship."
Q4: How did you ensure responsive design across devices?
Answer: "I applied a mobile-first responsive strategy. For cards and galleries, I used CSS Grid with repeat(auto-fit, minmax(280px, 1fr)), allowing cards to wrap automatically without requiring rigid media query breakpoints. For navigation, I engineered an off-canvas mobile drawer with a hamburger toggle that animates via CSS transforms."
